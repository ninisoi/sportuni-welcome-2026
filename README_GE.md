# SPORTUNI WELCOME 2026 — რეალური ვებსაიტი

ეს პროექტი შეიცავს დამტკიცებულ ვიზუალურ გვერდებს და Vercel-ის Flask სერვერულ კოდს. მონაცემები ინახება Supabase-ში. მონაცემთა ბაზაში არ არის საცდელი კითხვა ან პასუხი.

## გვერდები
- `/screen` — პროექტორი: QR ან Live Wall, რასაც მთავარი ადმინი აირჩევს
- `/join` — სტუდენტის პასუხის ფორმა
- `/confirmation` — პასუხის მიღების დადასტურება
- `/login` — უსაფრთხო შესვლა
- `/admin` — მთავარი ადმინი
- `/moderator` — დამხმარე მოდერატორი

## რა არის გასაკეთებელი გამოქვეყნებამდე
1. Supabase-ში უკვე გაშვებული საწყისი SQL-ის შემდეგ, **ცალკე** SQL Editor-ში გაუშვით `02_ADD_SECURE_OPERATIONS.sql`. ეს ამატებს ატომურ ოპერაციებს და არსებულ მონაცემებს არ შლის.
2. Supabase → Authentication → Users-ში შექმენით მთავარი ადმინისტრატორის მომხმარებელი ელფოსტითა და პაროლით. ჩაიწერეთ მისი UUID (User ID). **პაროლი არ დაამატოთ კოდში და არ ჩააკოპიროთ GitHub-ზე.**
3. SQL Editor-ში გაუშვით საკუთარი User ID-ით, შეცვლილი ქვემოთ მოცემული ბრძანება:
   `insert into public.staff_roles (user_id,role,is_active) values ('REPLACE_WITH_AUTH_USER_UUID','admin',true) on conflict (user_id) do update set role='admin',is_active=true;`
4. ამ საქაღალდის **შიგთავსი** ატვირთეთ GitHub Repository `ninisoi/sportuni-welcome-2026`-ის root-ში. **არ ატვირთოთ** `.env` ფაილი ან პაროლები. `.env.example` უსაფრთხო შაბლონია.
5. Vercel → Add New Project → Import Git Repository → მიუთითეთ `ninisoi/sportuni-welcome-2026`. Framework: Flask / Other (თუ ავტომატურად აღმოაჩენს Flask-ს, დატოვეთ). Root Directory: `./`.
6. Vercel → Project Settings → Environment Variables-ში შეიყვანეთ შემდეგი ცვლადები. **ყველა მნიშვნელობა მხოლოდ Vercel-ში**, არა GitHub-ზე:
   - `SUPABASE_URL`: Supabase-ის პროექტის URL
   - `SUPABASE_SERVICE_ROLE_KEY`: Supabase → Project Settings → API Keys → **secret** key `sb_secret_...` (მხოლოდ სერვერზე!)
   - `SUPABASE_ANON_KEY`: Supabase-ის **publishable** key `sb_publishable_...`
   - `FLASK_SECRET_KEY`: ძლიერი შემთხვევითი სტრიქონი მინ. 32 სიმბოლო
   - `DEVICE_HASH_SECRET`: სხვა ძლიერი შემთხვევითი სტრიქონი მინ. 32 სიმბოლო
   - `PUBLIC_BASE_URL`: საბოლოო HTTPS მისამართი, რომელსაც Vercel მოგცემთ
   - `OPENAI_API_KEY`: **არ არის აუცილებელი**. ცარიელი დატოვეთ თუ არ იყენებთ AI-ს. AI რეჟიმში ასეთ დროს ყველა პასუხი გადავა მოდერატორთან.
7. Deploy/Redeploy და შეამოწმეთ `/health`, `/login`, `/screen`, `/join`.
8. შედით მთავარი ადმინის ანგარიშით, გამოაქვეყნეთ პირველი რეალური კითხვა და აირჩიეთ მოდერაციის რეჟიმი **პარამეტრები** გვერდზე.

**მნიშვნელოვანი:** ეს ინსტალაციამდე და რეალური ტესტირებამდე არ ითვლება ღონისძიებისთვის შემოწმებულ სისტემად. 100–150 მონაწილემდე სცადეთ ტესტირება ათეულობით სხვადასხვა ტელეფონით. დარწმუნდით რომ Supabase და Vercel უფასო ლიმიტები საკმარისია.

## ძირითადი წესები
- სტუდენტის ბრაუზერს ენიჭება შემთხვევითი cookie. თითო კითხვაზე ერთ cookie-ზე მხოლოდ ერთი პასუხი მიიღება; cookie-ის წაშლის ან სხვა ბრაუზერის გამოყენების შემთხვევაში ეს შეზღუდვა შეიძლება გვერდის ავლით გამოიყენონ.
- საიდუმლო გასაღებები ყველა დროს სერვერზეა. საზოგადოებრივი გვერდები **არ კითხულობენ** სტუდენტების პასუხების მთელ ბაზას; ეკრანზე მხოლოდ მიმდინარე კითხვის დამტკიცებული პასუხები ჩანს.
- სტუდენტის წარუმატებელი გაგზავნა არ შლის ტექსტს. განმეორებითი გაგზავნა იყენებს იმავე submission UUID-ს; განმეორებითი ჩანაწერი ბაზაშიც იბლოკება.
- ადმინისტრატორის როლი Supabase `staff_roles` ცხრილშია; მოდერატორი მხოლოდ შემოწმებას მართავს. მთავარი ადმინისტრატორი მოდერატორს უფლებას მიანიჭებს ან გაუუქმებს ცალკე გვერდზე, როცა მოდერატორის Supabase Auth ანგარიში უკვე არსებობს.
- კითხვების შეცვლა ინახავს ძველ პასუხებს და პროექტორს ავტომატურად აბრუნებს QR-ზე.
- მოდერაციის რეჟიმებია `manual` (საწყისი, უსაფრთხო), `ai` (დაკავშირებული API თუ ხელმისაწვდომია), `direct` (გაუფილტრავი გამოქვეყნება). **Direct რეჟიმი რისკიანია** ღია აუდიტორიისთვის.
- ხელით დამტკიცებისას ორმაგი განხილვა იბლოკება ბაზის ატომური ოპერაციით.
- პარამეტრები შენარჩუნდება Supabase-ში, ადმინის პანელის ნავიგაცია პროექტორს არ გადართავს.
- CSV არქივი ხელმისაწვდომია მხოლოდ მთავარ ადმინთან.

## უსაფრთხოების შენიშვნა
მთავარი ადმინის შესვლა მუშაობს Supabase Auth-ის მომხმარებლით. რეალურ ღონისძიებაზე სასურველია პაროლის დაცვა და წვდომის კონტროლი; საჯარო GitHub არ ნიშნავს, რომ ადმინის მონაცემები საჯაროა. საიტი უზრუნველყოფს უფლებების სერვერულ შემოწმებას, მაგრამ უფასო სერვისების ლიმიტებისა და რეალური დატვირთვის გარანტია ჯერ ვერ გაიცემა.
